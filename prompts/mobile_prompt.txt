PROJECT CONTEXT (MANDATORY — FILL BEFORE REVIEW)

Project name: SELCO
Platforms: Android
App type: Internal

This Flutter application is designed to:
Support E4H/SELCO asset installation and AMC field workflows.
Let users log in, choose a role, and work as installation staff/supervisor or AMC user.
Manage installation reports: select facility, enter asset counts/specifications, add asset details, scan QR/barcodes, upload asset photos, installation images, certificates, and handover documents.
Support draft, inbox, approval, rejection, send-back, and submit-for-approval flows.
Support AMC scheduled visit/report workflows, including facility selection, dynamic forms, OTP, media uploads, drafts, and inbox handling.
Integrate with DIGIT/eGov services: OAuth login, MDMS configuration, localization, activity/workflow APIs, asset registry APIs, filestore uploads, role/action mapping, DIGIT UI/forms/scanner packages, location, notifications, and Firebase Analytics.
Networking uses Dio through a shared DioClient.
Auth uses OAuth password grant via user/oauth/token with a basic client authorization header. Access and refresh tokens are stored locally.
API requests are enriched by an interceptor with DIGIT-style RequestInfo, including auth token, user info, timestamp, action, API ID, and message ID.
The interceptor checks network/internet availability before requests.
On 401, the app attempts refresh-token recovery and retries the failed request; repeated/invalid refresh failures trigger logout/session expiry.
Offline behavior is cache-first/fallback in several places: MDMS/app config can fall back to stored data; activity/facility lists can fall back to Isar cache; unsent reports are stored as drafts.
Sync behavior includes manual/home-triggered sync of unsent drafts and background execution for long-running submit/reject/send-back/scheduled-visit operations. Progress and failure state are tracked in local Isar job records.
Data storage:
Isar is the main local database, opened as E4H, with collections for localization, activity/facility workflows, unsubmitted drafts, asset counts, specifications, asset details, uploaded media, installation images, BOM docs, AMC docs/media/forms, scheduled visits, sync records, operation checkpoints, and submission jobs.
FlutterSecureStorage stores sensitive/config data such as access token, access info, selected individual, app config, MDMS master data, form schemas, localization data, role actions, and cached form/config payloads.
SharedPreferences is also used for lightweight app preferences such as first-launch and selected locale state.
Background work:
Uses flutter_background_service with Android foreground service support and flutter_local_notifications.
Handles asset submission, rejection, send-back, and scheduled visit submission outside the immediate UI flow.
Writes operation progress, status, retry/error details, and completion state to Isar.
Requests Android notification permission and creates an “Asset Submission” notification channel.
Analytics:
Firebase is initialized on Android only.
FirebaseAnalytics is used through AppLogger; app log events are sent as app_log analytics events with level/title/message metadata.
